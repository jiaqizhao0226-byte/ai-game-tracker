## 已形成的关键产品原则

1. 判断「传统品类+AI」的核心问题：去掉 AI 后，玩法是否仍成立。
2. AI Native 按核心体验拆为 AI陪伴、AI叙事对话、AI玩法机制、AI社会/沙盒、AI生成UGC。
3. AI for Game 是研发侧工具与平台，用户是开发者，不进入玩家侧 AI Native / AI in Game 统计。
4. 主品类单选，跨类体验通过 `gameplay_facets` 表达。
5. 大厂系、多模态玩法等横向属性进入 `gameplay_theme`，不破坏主分类树。
6. 重点关注不是永久置顶理由；排序需要区分产品真实时间与补录时间。
7. 失败和停运产品保留，因为它们具有研究价值。
8. 正文采用八段式骨架；资料不足时宁可留空，不补造。

## 重要用户偏好与纠错

- 不使用绝对化表达，例如「第一个」「唯一」「必然」等，除非证据充分。
- 策略启示要收敛，不能从单一案例过度外推。
- 需要区分产品本体、AI介入点、商业表现与团队/资本信息。
- 页面应清晰、结构化、专业，视觉改动服务于信息理解。
- 实机截图比泛化宣传图更有研究价值。
- 不出现「光子策略分析组」。

## 技术历史

- Next.js 静态导出，生产环境使用 `/ai-game-tracker` base path。
- 曾处理 SSR 图片在 hydration 前加载完成导致 `onLoad` 不触发的问题。
- 截图画廊使用横向翻页与方向识别。
- 概览数字与饼图有入场动画，同时支持 reduced motion。
- 数据审计脚本历史上曾从大量问题清理到零问题；每次更新仍需运行。

## 使用原始会话的方法

不要把整份 JSONL 作为常驻上下文。需要追查某个历史决定时：

1. 先搜索本文件和 `docs/SCHEMA.md`。
2. 再按产品名、字段名或用户原话检索上述 JSONL。
3. 只读取命中的局部上下文。
4. 若旧回复与现行 schema 冲突，以现行 schema 和用户最新纠错为准。
